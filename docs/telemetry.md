# TTY profile generator

The profile is Markdown plus self-contained SVG images generated by a .NET 10
console application. It has no NuGet dependencies, third-party stats services,
external fonts, or JavaScript in the README. The terminal cursor is the only
animation and respects reduced-motion preferences.

## Run

From the repository root, with the .NET 10 SDK installed:

```sh
dotnet run --project profile -- --self-test
dotnet run --project profile -- --render data/profile.json
```

The second command is completely offline. To refresh the source data, set `GH_TOKEN`
in your environment and run `dotnet run --project profile -- --fetch`.
`PROFILE_LOGIN` defaults to `4booser`. Never put a token in a file or commit it.

GitHub Actions supplies its built-in repository token. No personal token is needed
for the normal public-profile workflow. Refreshes are scheduled every six hours
(00:17, 06:17, 12:17, 18:17 UTC), and can be triggered manually in the Actions tab.
GitHub may delay scheduled runs; the SVG and text summary show the actual snapshot
time. GitHub can disable schedules in public repositories after 60 days without
repository activity. If necessary, re-enable the workflow from its Actions page.

## Definitions

- The window contains 365 calendar dates, ending on the current UTC date.
- Contributions are GitHub's contribution-calendar entries, not all commits in all
  branches. The generator checks that the daily sum matches GitHub's total.
- An active day has one or more contributions. Work done without a GitHub contribution
  is not measured; neither working hours nor proficiency can be inferred from these counts.
- Current streak: consecutive active dates ending today, or yesterday while today
  is still empty. An empty yesterday breaks the streak.
- Longest streak: the maximum consecutive run inside the displayed window, not an
  all-time record. Last 30 days includes today and the preceding 29 dates.
- The contribution calendar may include anonymous private counts that the user has
  opted to display. Commit/PR/issue/review totals reflect the API token's visibility
  and need not add up to the calendar total. Repository-creation contributions are
  also not included in that four-part breakdown.
- Public repository count includes forks. Stars are summed over public, owned,
  non-fork repositories. The collector paginates beyond 100 repositories.
- Languages use GitHub's code-byte breakdown for public, owned, non-fork,
  non-archived repositories, excluding the profile repository itself. Percentages
  measure code volume, not time or ability. The five largest languages are shown
  individually; the rest are combined as Other. All values remain in the text summary.
- Calendar brightness uses the same explicit bins on desktop and mobile: 0, 1–3,
  4–9, 10–19, and 20+ contributions. Each day has an SVG title with its exact count.
- Recent activity means the last push to each public owned non-fork repository,
  not necessarily a commit authored by the profile owner.

The workflow commits generated files as `github-actions[bot]`, so the refreshes do
not create an artificial activity streak for the profile owner. The workflow token
does not trigger a recursive workflow run when it pushes generated files.

## Files and failure handling

- `profile/`: collector, calculations, renderer, tests, and README section updater.
- `data/profile.json`: public snapshot used to reproduce every displayed metric.
- `assets/`: desktop and mobile SVG variants, selected by the README's picture elements.
- README sections between `TELEMETRY` and `RECENT` markers are generated. Other prose
  is preserved. Missing or duplicate markers stop an update rather than overwrite text.

API errors, partial calendars, invalid counts, and malformed SVG output fail the job
before publication, preserving the last committed snapshot. A concurrent change to
the branch makes the push fail rather than overwrite someone else's work.
